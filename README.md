# GitHub CopilotでPythonのプロジェクトを改善する

この教材では、小さなPythonプロジェクトを読み、GitHub Copilotと一緒に改善します。コードの説明を受けるだけでなく、変更内容と実行結果を自分で確認することが目標です。

各フォルダーは**独立したプロジェクト**です。前のプロジェクトのファイルをコピーする必要はありません。READMEに示す順序で進めてください。

第14回では、第13回の復習と新しい説明の後、01から順に共同実習を進めます。最後の荷物管理では、同じプロジェクトを4段階で拡張します。

## 準備と実行

Python 3.10以上と、GitHub Copilot Proを利用できる環境を使います。PyCharmまたはVisual Studio Codeで、取り組む**一つのプロジェクトのフォルダー**を開いてください。

各READMEの実行コマンドは、そのプロジェクトのフォルダーを作業ディレクトリとして実行します。JSONのパスもそのフォルダーからの相対パスです。PyCharmの実行設定でも作業ディレクトリを合わせてください。

プロジェクトごとに仮想環境を作成できます。

```bash
python3 -m venv .venv
```

macOS / Linux:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

有効化後は、READMEの `python` コマンドを使います。IDEでも、この `.venv` のインタープリターを選択してください。01は追加ライブラリ不要です。02〜05には、それぞれ `requirements.txt` があります。

**テストは各プロジェクト内で別々に実行します。** 共通の名前のモジュールがあるため、`students` 全体を一度にpytestで収集しないでください。

## Copilotとの進め方

1. READMEで、現在の状態と完成後の条件を確認します。
2. 指定された順序でコードを読み、必要なファイルをCopilotへ添付します。
3. 対象のファイル、期待する動作、変更してはいけない内容を伝えます。
4. 提案された変更を読み、コマンドを実行する場合は内容と作業ディレクトリを確認します。
5. プログラムとテストを実行し、READMEの条件と比較します。

Ask、Plan、Agentの名称や利用可否は、エディターとプラグインのバージョンによって異なります。Planがない場合は「まず計画を説明し、まだ変更しないでください」とチャットで依頼してください。

未実装部分には `# TODO:` と `pass` があります。完成済みのコードも、読む対象や修正前の例として含まれています。変更後の解答コードは含めていません。

テストの成功だけを目的に、期待値を変えたりテストを削除したりしないでください。現在成功するテストだけでは、未実装の要件をすべて確認できません。

## 作業の記録と提出

各プロジェクトで作業後に `work_notes.md` を作成し、日本語で次の内容を残してください。

- Copilotへ送った主な依頼と、添付したファイル。
- 提案をそのまま採用したか、修正したか。その理由。
- 変更したファイルと、変更した動作。
- 実行したコマンド、実際の結果、確認した条件。

提出するものは、変更したソースコード、追加したテスト、`work_notes.md` です。`.venv`、キャッシュ、IDE設定、生成された `tasks_result.json` は提出不要です。提出先は教員の指示に従ってください。
