# 実習2 配送状態の履歴

実習1を完成させてから開始します。現在の状態に加え、どの状態を経て配達されたかを確認できるようにします。

## 完成条件

- Parcelに`history: list[str]`を追加し、初期値を`["受付済み"]`にします。荷物ごとに別のリストを持たせます。
- dispatch成功時に`配送中`、deliver成功時に`配達完了`を1回追加します。
- 不正な順序や繰り返しでValueErrorになった場合は、状態も履歴も変更しません。既存の例外メッセージを維持します。
- `build_history_report(service, tracking_number) -> str`をreport.pyに追加します。get_parcelを使って取得し、不明な番号の例外はそのまま伝えます。
- mainの既存表示を残し、最後に空行とP001の履歴を表示します。日時の記録は追加しません。

```text
履歴: P001
受付済み → 配送中 → 配達完了
```

末尾の改行は付けません。変更対象はparcel.py、report.py、main.py、tests/です。履歴の追加処理をDeliveryServiceとParcelの両方に書かないでください。

## 確認するケース

初期履歴、発送後、配達後、失敗した操作、別の荷物への影響がないこと、履歴レポート、不明な番号をテストします。既存の検索と発送・配達のテストも実行します。

## Copilotへの依頼

```text
実習2の仕様を読んで、履歴をどのクラスで更新するか説明してください。
失敗時に履歴が増えないことと、荷物ごとにリストが独立することを計画に含めてください。
今は実装せず、実習3以降は追加しないでください。
```

計画確認後に実装を依頼し、差分、テスト、main.pyの出力を確認します。
